Using R to retrieve data from the GSS StatsBank API

A practical guide to navigating the GSS StatsBank API and retrieving 2021 Population and Housing Census data with R.

Published

November 26, 2025

View the original Gist on GitHub

Background

The Ghana Statistical Service (GSS) provides survey and census data through the StatsBank. Usually, users visit the website, find a table, and download it as an Excel or CSV file.

However, if you are working on a large project or need to update your data frequently, downloading files manually can be tedious. A better approach is to use R to retrieve this data programmatically. The StatsBank website actually provides a built-in option to view the “API Query” for any table, which allows us to automate this process.

This guide will walk you through how to connect to the GSS API and download specific statistics—specifically using the 2021 Population and Housing Census (PHC) data.

Prerequisites

We will use the httr2 package to handle HTTP requests and response, and tidyverse for any data munging tasks.

library(httr2)
library(tidyverse)

Part 1: Connecting to the API

The StatsBank API is built on PxWeb technology, a standard used by many statistical agencies. Think of the API like a file explorer on your computer: it has a hierarchy of “folders” (Databases and Levels) that eventually lead to “files” (Tables).

We start by defining the base URL for the GSS API:

URL = "https://statsbank.statsghana.gov.gh:443/api/v1/en/"
request = request(URL)

Automating the Navigation

Navigating deeper requires updating the URL path repeatedly. To make this easier, we can create a helper function.

We will design this function to:

  1. Accept our base URL and a list of folder names.
  2. Check if we have reached a final table (which ends in .px in the PxWeb system).
  3. If it is a folder, list the contents so we know where to go next.
  4. If it is a table, list the available variables (metadata) to help us build our query.
  5. Return the updated request object so we can save it and use it later.
build_url = function(URL, ...) {
    path = list(...)
    req = request(URL)
    
    # Add each folder name to the URL path incrementally
    full_req = purrr::reduce(path, req_url_path_append, .init = req)
    
    # Check if the last part of the path ends in ".px" (indicating a table)
    is_table = FALSE

    if (length(path) > 0) {
      if (grepl("\\.px$", path[[length(path)]], ignore.case = TRUE)) {
        is_table = TRUE
      }
    }

    # Fetch the content to see what is inside (GET request)
    response = req_perform(full_req)
    body = resp_body_json(response)

    if (is_table) {
        # If it is a table, print the variable names (metadata)
        message("Endpoint reached: Table found.")
        message("Available variables:")
        print(map_chr(body$variables, "code"))
    } else {
        # If it is a folder/database, list the children IDs
        # (Note: The root level (databases) uses 'dbid', sub-levels use 'id')
        key = if(length(path) == 0) "dbid" else "id"
        print(map_chr(body, key))
    }

    # Return the request object to be assigned to a variable
    return(full_req) 
}

Part 3: Constructing the Query

Since we saved our connection in the table_req object, we only need to focus on what data we want to retrieve.

The instructions must be sent as a JSON object. This object has two main parts:

  1. Query: Which variables and filters to apply (e.g., specific regions or categories).
  2. Response: The format we want the file in (e.g., csv or json). A list of formats is available in the API documentation.

Defining the Variables

According to the API documentation, we select data using a code (the variable name we saw in the previous step) and a selection. Refer to the API documentation for other filter options.

  • Filter “item”: Selects specific values listed.
  • Filter “all”: Selects everything (using the wildcard *).

Here is how we construct a query to get data on specific “Water Disposal” methods:

# Construct the JSON query in R
query_list = list(
  query = list(
    list(
      code = "WaterDisposal",
      selection = list(
        filter = "item",
        values = list(
          "Total households in occupied dwelling unit",
          "Through the sewerage system") # Selecting one specific method
      )
    ),
    # We must select values for other variables or the API might aggregate them
    list(
       code = "Geographic_Area",
       selection = list(filter = "all", values = list("*"))
    )
  ),
  response = list(
    format = "csv" # We want the data back as a CSV
  )
)

How do we know what values to use in the query?

You might be wondering: How did we know to use “Through the sewerage system” as one of the variable values?

The API provides “metadata” for every table, which acts like a menu of options. Since we saved our request in the table_req object earlier, we can inspect it to see exactly what choices are available for each variable.

Here is how to peek inside the “WaterDisposal” variable to find the valid codes:

# 1. Fetch the metadata for the table
metadata = table_req |> 
  req_perform() |> 
  resp_body_json()

# 2. Find the variable we are interested in (e.g., WaterDisposal)
# This filters the list of variables to find the one with the code "WaterDisposal"
variable_info = metadata$variables |> 
  purrr::keep(~ .x$code == "WaterDisposal") |> 
  purrr::flatten()

# 3. Print the available options 
tibble(
  Code = unlist(variable_info$values)
)

Part 4: Retrieving and Parsing the Data

Finally, we put it all together. We take our saved table_req object, attach the query using req_body_json, and perform the request.

Note that the API requires a POST request to retrieve the actual data. Once we get the response, we can pipe it directly into readr::read_csv() to create a dataframe.

The raw data often comes in a “wide” format (with regions as columns), so we can use tidyr to pivot it into a tidy format for analysis.

# Attach the query to our existing request object
final_req = table_req |> 
  req_body_json(query_list)

# Perform the request 
response = 
  final_req |> 
  req_perform()  

# Parse the data
data = 
  response |> 
  resp_body_raw() |> 
  readr::read_csv() |> 
  tidyr::pivot_longer(
    cols = -1, 
    names_to = "Geographic_Area", 
    values_to = "count" 
  ) |>
  tidyr::pivot_wider(
    names_from = 1, 
    values_from = count) |> 
  rename(total_households = `Total households in occupied dwelling unit`,
  sewerage_diposal = `Through the sewerage system`)

Summary: The Complete Script

Here is the full code from start to finish. You can copy and paste this directly into your R script to retrieve the data.
